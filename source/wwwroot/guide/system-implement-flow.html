EFrame 事件订阅框架 — 系统实施与使用流程

推荐路径：先填 Excel → 第一步投产导入（框架 SQL + 01~17）→ 重新登录 → 抽查联调 → 日常业务。

导入一次写入的内容： 组织（部门/岗位/职责/用户/任岗）+ 菜单订阅 + 事件配置 + 流转规则（Tbl_E_EventFlowRule） + 仪表盘（可选）。
核心链路：用户 → 任岗 → 岗位职责 → 职责 → 订阅 → 发布事件 → 流转规则 → 待办/通知。

准备 — 填表（导入前由公司完成）

应用负责人员接收签字表格，整理为 Excel 01~17（或使用「模板-贸易公司默认」）。
对应：A02 部门 → A03 岗位 → A04 职责 → A05 岗位职责 → A06 用户任岗 → A07 菜单 → A08~A10 事件/规则/订阅 → A11 仪表盘（可选）。

第一阶段 — 投产数据导入（实施第一步）

1、确认 Web 已部署、appsettings.json 连接串正确； /health 显示数据库 Connected。

2、用初始管理员登录（种子账号如 cfadmin / 123456，或已有管理员）。

3、投产数据导入 — 默认顺序：框架 SQL（10/11/20/23）→ 清空原组织 → 导入 Excel 01~17；支持 ZIP 一次上传

4、查看导入报告，确认 07 表用户、11/14 订阅与流转规则无报错。

5、全员退出重新登录，使用 Excel 07 中的 LoginId + 初始密码（默认多为 123456）。

6、若菜单无「投产数据导入」，在库中执行一次 scripts/27-Patch_EDataImport_Menu.sql 后重新登录。

第二阶段 — 导入后抽查（一般不必逐条手工录入）

以下数据已含在 Excel 导入中，仅在需要核对或微调时点菜单：

1、部门 / 岗位 / 职责 / 用户任岗 — 抽查 A02~A06

2、订阅管理 / 资源权限 — 抽查 A07 菜单是否齐全

3、事件配置 / 事件流转规则 — 抽查 A08/A09（Tbl_E_EventFlowRule）

4、抽 3 个用户登录，确认侧栏菜单、任岗切换正常。

第三阶段 — 事件与流转规则联调

1、事件发布 Demo — 发布 Excel 13/14 中配置的 EventCode，验证待办是否落到正确职责

2、事件实例 / 待办任务 — 确认 CREATE_TODO 规则生效

3、人事请假（内置完整示例）： 申请 → 审批

4、贸易 TRADE.* 等业务：页面开发完成后在代码中 PublishAsync；开发前用 EventDemo 模拟。

第四阶段 — 公司开张，大家开始用

1、登录，多任岗在首页切换。

2、首页 / 工作台

3、待办任务 — 处理审批

4、仪表盘 可选— 若导入 15~17

第五阶段 — 上线后增量（少量变更时再用界面）

1、新增人员 → 用户 + 任岗

2、新增菜单 → B01：资源 + 订阅

3、新增事件/规则 → B02：事件 + 流转规则 + 开发 PublishAsync

4、大批量变更 → 改 Excel 后再次 投产导入（默认全量覆盖）

5、字典/选项 → 字典维护

6、人员交接 → 用户交接

注意：改组织、订阅、流转规则后，相关用户需 退出重新登录。
